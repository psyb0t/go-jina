# go-jina

Unofficial Go client for the Jina AI APIs, generated from Jina AI's OpenAPI documents. If you only want to use the client from an agent, read [.agents/skills/go-jina/SKILL.md](.agents/skills/go-jina/SKILL.md) instead; this file is about changing the code.

## Architecture

Two generated packages, each from its own spec:

| Package | Spec | Output |
|---|---|---|
| `jina` (root) | `https://api.jina.ai/openapi.json` | `client.gen.go` |
| `jinareader` (`reader/`) | `https://r.jina.ai/openapi.json` | `reader/client.gen.go`, `reader/models.gen.go` |

Data flow per package, declared in its `gen.go`: `scripts/fetch-spec.sh` (download into the gitignored `api/`) → `scripts/fix-spec.sh` with a jq filter (`api/*.fixed.json`) → `go tool oapi-codegen` with the package's config → generated files.

## Stack

- Go 1.26.9. oapi-codegen v2 as a `go.mod` tool; `github.com/oapi-codegen/runtime` at runtime.
- jq for the spec patches. No hand-written library code.

## Layout

- `gen.go`, `config.yaml`, `client.gen.go`, `client_test.go`, `example_test.go`: the `jina` package.
- `reader/`: the `jinareader` package, with `config.yaml` (client) and `config.models.yaml` (models).
- `scripts/`: spec fetch, spec patch filters, lint and security scan scripts.
- `api/`: downloaded specs, gitignored, never committed.
- `vendor/`: committed, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make generate  # download the specs, patch them, regenerate
make dep       # go mod tidy + go mod vendor
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- The embedding and rerank bodies are `oneOf` unions. Inline, oapi-codegen makes the request body a defined type over the union, which drops its `MarshalJSON`, and the client sends `{}`. `fix-jina-spec.jq` moves them into components so the body type is an alias. A new union body upstream gets the same treatment only if it has a `title`; `TestEmbeddings` and `TestRerank` decode the sent body and fail on `{}`.
- The Reader's `{url}` path parameter becomes `{targetUrl}`, so the method is `GetTargetUrl`, not `GetUrl`. A parameter named `url` shadows `net/url` in the generated code.
- Untyped Reader query or header parameters are generated as a non-pointer `interface{}` that is always sent; a nil value panics in the runtime. `fix-reader-spec.jq` types them as strings.
- semgrep's `unsafe-deserialization-interface` rule is excluded in `scripts/sec.sh`. oapi-codegen decodes untyped response schemas (the batch downloads) into `interface{}`, which the spec leaves no way around.
- The CI pipeline skips the generate drift check, because the specs change upstream without notice. Regenerate locally and commit the result.
- `.github/workflows/regen.yml` regenerates the client every day and releases the result. When the checks fail, Claude edits the repository to fix them, but a fix may not touch the paths listed under `fix_protected_paths` in that workflow: the workflows, the Makefile, `AGENTS.md`, `.agents/rules/`, the lint, security and spec download scripts and their configs. A problem that needs a change there fails the run and needs a manual fix.
